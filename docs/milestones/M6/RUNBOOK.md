# M6 local runbook

처음 실행하는 사용자를 위한 명령별 안내: [한국어 실행 안내](../../GETTING_STARTED.ko.md).

Use Python3.12 from `uv sync --frozen` / `.venv/bin/python`, and Node22 with `npm --prefix frontend ci`. On this host bare python3 is3.9 and default Node25 is unusable; tested Node22 is `/opt/homebrew/opt/node@22/bin`. Processes do not auto-load .env.example. Export implemented Settings explicitly; field/chunk policy and shared source throttling are typed API configuration, not legacy draft env knobs.

Native separate processes: `.venv/bin/python -m almrag.cli migrate`, `.venv/bin/python -m almrag.cli bootstrap-admin`, `.venv/bin/python -m almrag.api`, `.venv/bin/python -m almrag.worker`. Bootstrap has no default production credentials and prompts securely. Run API/worker against the same local SQLite filesystem/reader-lock directory; shared NFS/multi-host DB is not supported. Browser administrator sessions require HTTPS reverse proxy at ALMRAG_ALLOWED_ORIGIN; no weakening Secure/HttpOnly/SameSite/CSRF. Frontend is built with npm run build and served separately with same-origin /api/v1 proxy. API key mode remains browser-memory only.

Local Compose: `DOCKER_CONTEXT=colima-alm-rag docker-compose -p almrag-dev -f deploy/compose.yaml build`, then `up -d --wait`. Default loopback8000/8080 serves development health; live ALM/model/vector/Notion remain disabled. Separately authorized service setup must supply explicit trusted URLs, CA/secret references and enabled flags to both API and worker; Compose does not forward arbitrary host environment automatically. API/worker uid10001, frontend uid101. Ordinary stop/down retains data volumes; do not use down -v for customer data.

Quality REST: POST projects/{p}/evaluation-datasets with strict bounded `{cases:[{query,relevant_item_uids}]}` obtains opaque dataset_ref. POST projects/{p}/evaluations with project_uids exactly[p], dataset_ref, unique methods dense/keyword/hybrid and top_k1..100. POST projects/{p}/integrity queues read-only check. All enqueue/stage actions require project_manage. GET jobs/{j}/quality-report requires project_read and returns409 until completed. API/worker preserve durable FIFO, immutable hashed request and fenced atomic report/terminal transition. Foreign project IDs/relevant Items are rejected before search. No URL/path dataset fetch exists.

CLI: `almrag stage-evaluation <project> <local-json-file>`, `almrag evaluate <project> <dataset-ref> --top-k 10`, `almrag integrity <project>`, `almrag quality-report <job>`. CLI uses authenticated API via ALMRAG_API_URL/ALMRAG_API_KEY; never opens a customer DB for destructive repairs.

Interpret integrity per check, not only overall status: live ALM completeness is NOT VERIFIED because source is not contacted. Missing vector capability/unsupported historical processor version is NOT VERIFIED; proven raw/type/field/attachment/normalization/chunk/provenance/index inconsistencies are FAIL. Issues include bounded Item/revision/check IDs and explicit recovery/index rebuild action. Existing failed-item references can be retried through project_manage replay controls from M4/M5. Corrupt storage is not silently repaired: restore a trusted raw backup to a fresh recovery directory and reprocess/embed/index; authentication must be re-registered. Actual model tokenizer recount/calibration remains NOT VERIFIED.

Evaluation metrics are macro Item-level Precision@K (K denominator), Recall@K and MRR, duplicates removed. Dense/Keyword are pure channels; only Hybrid adds metadata exact-ID boost. Identical authorized project/top_k/compact restoration and generation/revision/membership/config pins apply; drift/backend errors fail rather than becoming zero scores. A PASS means calculations executed, not a prescribed semantic-quality threshold. Use20–50 human-judged project queries including identifiers, Korean paraphrases and table semantics when real calibrated model access is supplied.

Validation: `.venv/bin/python tools/validate_baseline.py` and `tools/validate_release.py` are static documentation/CI-presence checks only. Actual tests: `env ALMRAG_TEST_QDRANT_URL=http://127.0.0.1:16333 .venv/bin/pytest -q` against the dedicated synthetic test instance; `npm --prefix frontend test`, `npm --prefix frontend run build`, `npm --prefix frontend run test:e2e`. E2E additionally starts a disposable HTTPS API/worker fixture on19443 with self-signed temporary test key; ignoreHTTPSErrors applies only to that test context, no OS trust change. Ports4173/19443 must be free. Remote CI remains NOT VERIFIED until run at an authorized remote destination.
