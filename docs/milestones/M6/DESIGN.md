# M6 design

Quality work uses existing durable global FIFO, fenced jobs and immutable project-bound snapshots; reports are separately persisted and readable only by authorized project owners. INTEGRITY and EVALUATE are explicit stages. Golden datasets are staged as strict bounded project-bound JSON with opaque references (no external URL/path loading). Evaluation validates every relevant Item owner and dataset/project match before retrieval; backend worker repeats ownership validation. A query or Item text is project-sensitive and never published to external summary outbox.

Search default remains hybrid. Internal evaluation method dense/keyword/hybrid selects actual channels, with identical authorized project/generation/Item restoration filters and Item-level denominators. Exact-ID boost policy is recorded in evaluation evidence. Keyword comparison must not invoke embedding/model or dense query. Missing/corrupt backend must not become silent metric zeros. Macro P@K uses K denominator even fewer returned, Recall unique relevant Items and MRR first relevant rank, cut at K. Persist explicit generation references; reject generation changes across a comparison rather than claim comparable quality.

Integrity compares locally retained source observations/latest mappings, raw hash/fields/attachments, processing coverage/chunk bounds, keyword and dense prepared publication evidence. Actual ALM completeness remains NOT VERIFIED without contacting source. Read-only report must never rewrite active pointers or repair customer data automatically. Use existing explicit replay/rebuild controls for correction. Missing vector runtime makes dense check NOT VERIFIED, never PASS. Isolated synthetic corruption tests establish detection.

100k benchmark generates owned temporary synthetic records, measures actual ingestion/publication/search channels and size/chunk distribution; only sanitized aggregate measurements are retained. Real model is not configured, so fixture latency is explicitly distinct from SRS036 warm-Ollama target. Embedding harness collects environment, chunks/s,tokens/s,batch/changed ratio when caller explicitly supplies authorized runtime; default tests use stubs. No throughput guarantee inferred from mocks.
