# ALM RAG 웹 UI 사용 설명서

현재 M6 웹 화면 기준 한국어 설명서입니다. 화면의 메뉴·버튼 이름을 그대로 사용합니다. 설치는 [한국어 실행 안내](GETTING_STARTED.ko.md), Linux 다운로드와 접속은 [Linux 검증 절차](LINUX_VALIDATION.ko.md)를 먼저 확인하세요.

## 1. 지금 실행한 환경부터 확인하기

| 실행 환경 | 가능한 확인 | 제한 |
|---|---|---|
| `tools/native_e2e_server.py` | 임시 관리자 로그인, 합성 프로젝트 표시, 무결성 작업과 보고서, 로그아웃 | 임시 DB이며 종료 시 정리됩니다. 실제 ALM·모델·벡터 연결은 꺼져 있습니다. 실제 서버 등록·SYNC·검색 검증용이 아닙니다. |
| 일반 API + Worker + HTTPS 웹 서버 | 설정된 ALM 등록·수집, 검색, 운영 기능 | 같은 DB와 필요한 환경설정을 API·Worker에 전달해야 합니다. 실제 ALM·모델은 별도 연결 검증이 필요합니다. |
| 기본 Compose HTTP 8080 | 화면 및 health 확인 | Secure 관리자 로그인에는 별도 HTTPS 프록시와 일치하는 Origin이 필요합니다. |

데모 서버의 `Settings`는 고정되어 있습니다. 환경변수만 export해도 실제 ALM 연결이 활성화되지 않습니다. 실제 연결은 일반 실행 환경에서 준비합니다.

### 데모에 접속하기

저장소 루트에서 실행합니다. `frontend` 폴더 안에서 실행하는 명령이 아닙니다.

```bash
npm --prefix frontend run build
uv run python tools/native_e2e_server.py
```

Linux 자체 브라우저에서 `https://127.0.0.1:19443/`를 엽니다. 브라우저가 다른 PC에 있다면 그 PC의 터미널에서 다음 SSH 터널을 유지합니다. 계정과 주소는 실제 값으로 바꾸세요.

```bash
ssh -N -L 19443:127.0.0.1:19443 사용자명@리눅스서버주소
```

그 PC의 브라우저에서 같은 HTTPS 주소를 엽니다. 데모는 임시 자체 서명 인증서를 사용하므로 인증서 경고가 표시될 수 있습니다. 서버 IP로 직접 접속하는 방식은 지원하지 않으며, 공개 바인딩으로 변경할 필요도 없습니다.

## 2. 작업 공간 연결과 세 종류의 인증

| 구분 | 어디에 사용하는가 | 입력/설정 위치 |
|---|---|---|
| ALM RAG 관리자 계정 | 이 웹 UI의 관리 기능 | 첫 화면의 **관리자 세션으로 연결** |
| ALM RAG API 키 | 권한이 부여된 프로젝트 접근 | 첫 화면의 **API 키** |
| Codebeamer/Polarion 자격증명 | 원본 ALM의 REST API 접근 | 서버 환경변수 또는 등록된 vault 비밀 값 + **서버 등록**의 자격증명 참조 |

Codebeamer 비밀번호를 첫 화면의 관리자 비밀번호나 API 키 칸에 입력하지 마세요. 서로 다른 인증입니다.

### 관리자 세션

1. **관리자 세션으로 연결**을 펼칩니다.
2. **관리자 이름**, **관리자 비밀번호**를 입력합니다.
3. **관리자 로그인**을 누릅니다.

데모 전용 계정은 `synthetic-admin` / `synthetic browser password`입니다. 일반 실행 환경에는 이 기본 계정이 없습니다. 운영 담당자가 같은 DB에서 `uv run python -m almrag.cli bootstrap-admin`으로 최초 계정을 생성해야 합니다. 관리자 비밀번호는 16자 이상이어야 합니다.

관리자 세션에는 HTTPS가 필요합니다. 브라우저 주소의 Origin과 API의 `ALMRAG_ALLOWED_ORIGIN`이 일치해야 합니다.

### API 키와 연결 해제

발급받은 ALM RAG 키를 **API 키**에 입력하고 **API 키로 연결**을 누릅니다. 키는 브라우저 메모리에서만 사용하며 새로고침 뒤에는 다시 연결합니다. API 키 발급·프로젝트 권한 부여는 현재 이 웹 UI에서 제공하지 않으므로 관리자에게 요청합니다.

오른쪽 위 **연결 해제**는 관리자 세션이면 로그아웃하고, API 키 연결이면 브라우저 연결 상태를 지웁니다. API 키 자체를 폐기하는 기능은 아닙니다.

## 3. 메뉴와 권한

| 왼쪽 메뉴 | 주요 기능 | UI 접근/실행 조건 |
|---|---|---|
| 프로젝트 | 프로젝트 확인, SYNC·단계별 작업 | 작업 생성은 해당 프로젝트의 `project_manage` 또는 관리자 |
| 서버 등록 | ALM 연결·프로젝트 등록 마법사 | 관리자 세션 |
| 검색 · Explorer | 프로젝트 검색, 원본·Revision·Chunk 조회 | 검색은 `search`, 원본 조회는 `project_read` 또는 관리자 |
| 작업 · 실패 목록 | 작업 상태·이벤트·실패 Item·재처리 | 조회는 프로젝트 읽기 권한, 재처리·재개는 `project_manage` 또는 관리자 |
| 백업 · 패키지 | 프로젝트 ZIP Export/Import, 로컬 백업·격리 복구 | Export·업로드·Import는 `project_manage`, 목록·다운로드는 `project_read` 또는 관리자. 전역 백업·복구는 관리자 세션 |
| 감사 로그 | 감사 기록 조회 | 관리자 세션 |
| 검색 평가 | 무결성·골든셋 평가·보고서 | 작업 생성은 `project_manage`, 보고서 조회는 `project_read` 또는 관리자 |

버튼 비활성은 권한 부족뿐 아니라 필수 입력 누락, 처리 중, 현재 작업 상태 때문에 발생할 수 있습니다. `Available`은 API health 응답 상태이며, 실제 ALM·Ollama가 연결됐다는 뜻이 아닙니다.

## 4. Codebeamer Basic 인증: 비밀번호는 어디에 넣는가

현재 화면에는 ALM 비밀번호 직접 입력칸이 없습니다. **사용자 이름은 화면에, 비밀번호는 서버 환경변수에, 화면의 자격증명 참조에는 환경변수 이름**을 입력합니다.

| 서버 등록 항목 | 예시 |
|---|---|
| ALM 종류 | Codebeamer |
| 서버 표시명 | 테스트 Codebeamer |
| 서버 기본 URL | `https://codebeamer.example.invalid` (예시이며 실제 승인된 주소로 변경) |
| Codebeamer 인증 방식 | Basic |
| Codebeamer 사용자 이름 | 해당 서버의 실제 로그인 ID |
| 자격증명 참조 | `env:CODEBEAMER_PASSWORD` |
| CA 번들 참조 (선택) | 사설 CA가 필요할 때 `env:ALM_CA_BUNDLE` |

Linux Bash에서 **일반 API와 Worker를 시작할 터미널 각각** 다음과 같이 숨김 입력합니다.

```bash
read -r -s -p "Codebeamer 비밀번호: " CODEBEAMER_PASSWORD
echo
export CODEBEAMER_PASSWORD
```

그 환경에서 API·Worker를 시작하거나 재시작해야 합니다. 다른 터미널에서 export한 값은 이미 실행 중인 프로세스에 전달되지 않습니다. 비밀번호 값만 저장하며 `사용자명:비밀번호`나 Base64 인코딩 값은 넣지 않습니다. 서버가 사용자 이름과 비밀번호를 조합해 Basic 인증 헤더를 만듭니다.

일반 실행의 실제 ALM 연결에는 API·Worker 양쪽에 다음 설정도 필요합니다. 대상 주소는 예시를 실제 승인된 ALM Origin으로 바꾸며, Origin에는 경로를 넣지 않습니다.

```bash
export ALMRAG_LIVE_ALM_ENABLED=true
export ALMRAG_ALLOWED_ALM_ORIGINS="https://codebeamer.example.invalid"
```

이 두 설정만으로 검색 준비까지 완료되는 것은 아닙니다. 수집 연결 검증과 별도로 모델·토크나이저 프로필, 벡터 저장소 등 파이프라인 준비가 필요합니다. 일반 API·Worker·HTTPS 실행은 [실행 안내](GETTING_STARTED.ko.md)를 따릅니다.

CA 번들 참조는 **인증서 파일 경로가 들어 있는 환경변수**를 가리킵니다. 예를 들어 `ALM_CA_BUNDLE=/etc/ssl/local/alm-ca.pem`을 해당 프로세스에 전달하고 파일을 읽을 수 있게 준비합니다. TLS 검증을 끄는 옵션으로 우회하지 않습니다.

Compose는 호스트의 임의 환경변수를 자동 전달하지 않습니다. 기본 Compose에는 이 ALM 비밀번호·허용 Origin·live 플래그 전달 구성이 없으므로, 컨테이너 API·Worker 양쪽에 명시적으로 전달하는 환경별 구성이 필요합니다. 단순히 호스트에서 export한 뒤 기존 Compose를 재시작하는 것만으로는 충분하지 않습니다.

`vault:이름` 참조는 비밀 값이 서버 vault에 미리 등록되고 마스터 키가 준비된 경우에만 사용합니다. 참조 이름만 입력하면 비밀 값이 자동 등록되는 기능은 없습니다. `.env.example`도 자동으로 읽히지 않습니다.

### Bearer 인증과 Polarion

Codebeamer에서 Bearer를 선택하면 사용자 이름 대신 토큰을 서버 비밀 값에 설정합니다. 예를 들어 `env:CODEBEAMER_TOKEN`은 해당 환경변수의 토큰을 참조합니다. 현재 Polarion 등록 화면은 Bearer 방식이며 `env:POLARION_TOKEN`처럼 설정합니다. 화면에 실제 토큰을 입력하지 않습니다.

## 5. 서버·프로젝트 등록 마법사

실제 ALM에 접근 가능한 일반 실행 환경에서 관리자 세션으로 진행합니다.

1. **서버 등록**에서 **ALM 종류**를 선택합니다.
2. 서버 표시명·기본 URL·자격증명 참조·인증 방식을 입력합니다. Codebeamer는 뒤에 `/v3/...`를 조합하므로 해당 경로 앞의 서버 기준 주소(예: `https://cb.example.invalid/cb`)를 사용합니다. Polarion은 뒤에 `/projects/...`를 조합하므로 REST API 기준 주소(예: `https://po.example.invalid/polarion/rest/v1`)를 사용합니다. 예시의 컨텍스트 경로는 실제 배포 설정에 맞춰야 하며 개별 프로젝트 자원 URL은 입력하지 않습니다.
3. **서버 저장 · 연결 검증**을 누릅니다. 등록 후 연결 검사와 프로젝트 탐색을 수행합니다. **기존 서버 프로필 재사용 → 서버 목록 조회**로 저장된 프로필을 선택할 수도 있습니다.
4. **원본 프로젝트**를 선택합니다. Codebeamer는 실제 **Tracker**, Polarion은 **Work Item Type** 목록을 탐색합니다. Codebeamer의 Tracker 종류 이름과 실제 Tracker ID는 다릅니다.
5. 전체 수집이면 **모든 Tracker 수집** 또는 **모든 Work Item Type 수집**을 유지합니다. 일부만 수집하려면 해제하고 표시된 목록에서 선택합니다.
6. **임베딩할 필드**를 선택합니다. 기본값은 정규화 Title·Description입니다. 임베딩 필드 선택은 원본 전체 보존과 구분됩니다.
7. **초당 요청 수**, **최대 동시 요청**, **최소 요청 간격 (ms)**을 서버 정책에 맞춥니다. 화면 초기값은 각각 2, 2, 200입니다.
8. **저장 전 정책 미리보기**를 확인하고 **프로젝트 · 정책 저장**을 누릅니다.
9. **사전 검증 실행**을 누릅니다. `status=READY`, `sync_ready=true`이며 설정 revision이 확인되어야 **검증된 프로젝트 동기화**가 활성화됩니다.
10. 동기화 요청 뒤 **작업 · 실패 목록**에서 진행 결과를 확인합니다.

설정 변경 후에는 이전 사전 검증 결과를 재사용하지 말고 다시 검증합니다. 응답에 작업 ID가 나왔다는 사실만으로 수집 완료를 뜻하지 않습니다. 실제 ALM 버전별 호환성은 대상 서버에서 확인해야 합니다.

## 6. 프로젝트: 동기화와 단계별 작업

**새로 고침**으로 접근 가능한 프로젝트 목록을 갱신합니다. **동기화 SYNC**는 파이프라인 작업을 요청합니다. **단계별 작업**을 펼치면 다음 기능이 있습니다.

| 버튼 | 의미 |
|---|---|
| COLLECT | 선택한 원본 ALM 자료 수집 |
| PROCESS | 보존 원본 정규화 및 Chunk 생성 |
| EMBED | 준비된 모델로 임베딩 생성 |
| INDEX | 처리 결과를 검색 인덱스에 반영 |
| REBUILD_INDEX | 인덱스 재구축 요청 |
| 동기화 사전 검증 | 현재 프로젝트의 파이프라인 준비 상태 확인 |

처음에는 마법사의 사전 검증·동기화 순서를 사용하세요. 개별 단계는 이전 단계의 준비 상태와 모델·벡터 설정이 갖춰져 있어야 하며, 요청 성공만으로 해당 단계 완료를 판단하지 않습니다.

## 7. 검색 · Explorer

1. **검색어**를 입력합니다. 원본 Item ID나 문장으로 검색할 수 있습니다.
2. **검색 프로젝트 (명시적으로 선택)**에서 하나 이상 선택합니다. 선택하지 않으면 검색 버튼이 비활성입니다.
3. **Top K**를 1~100 사이로 설정합니다. 기본은 10입니다.
4. 필요하면 **원본 Item ID 필터**, **Scope ID 필터**에 쉼표로 구분한 ID를 입력합니다. 이름이 아니라 해당 소스의 ID를 사용합니다.
5. **전체 원본 포함**은 검색 응답에 전체 원본을 포함할 때 선택합니다.
6. **검색 실행**을 누릅니다. 결과의 제목을 누르면 Item 상세가 열립니다.

**일치 Chunk**에는 입력 텍스트와 원본 위치 정보가 표시됩니다. Item 상세에서는 **전체 원본 JSON**, **정규화 Block · Table · provenance**, **모든 Chunk · 토큰 수 · Hash**, **Revision · Hash 이력**을 펼칠 수 있습니다.

**프로젝트 원본 목록 → 프로젝트 이름 원본 조회**로 검색 인덱스가 없는 Item의 보존 원본도 확인할 수 있습니다. 보존된 최신 원본을 표시한다는 경고는 활성 검색 인덱스가 없다는 뜻입니다.

**HTML 원본 필드**를 선택하거나 **HTML 미리보기 원본**에 HTML을 붙이면 제한된 구조만 표시합니다. 스크립트·이미지·외부 링크 동작 등은 원본 페이지처럼 실행되지 않습니다. 미리보기 한도 경고가 뜨면 전체 원본 JSON에서 확인합니다.

검색 점수는 정답 확률이 아닙니다. 인덱스 없는 프로젝트 경고나 조회 한도 경고가 뜨면 데이터 준비 상태 또는 검색 범위를 확인합니다. 데모에는 실제 검색 모델·인덱스가 준비되어 있지 않습니다.

## 8. 작업 · 실패 목록과 재처리

**작업 새로 고침**을 눌러 최신 상태를 확인합니다. 현재 화면은 작업 완료를 자동으로 계속 갱신하지 않습니다. 작업 ID를 누르면 실패 목록·이벤트·진단을 조회합니다.

| 상태 | 읽는 방법 |
|---|---|
| QUEUED / RUNNING | 대기 / 실행 중. Worker가 실행 중인지 확인합니다. |
| SUCCEEDED | 해당 작업 실행 성공. 실제 ALM 완전성이나 검색 품질을 별도로 보장하는 표시는 아닙니다. |
| COMPLETED_WITH_ERRORS | 일부 Item 실패가 남은 상태로 완료. 실패 목록을 확인합니다. |
| PAUSED / BLOCKED | 원인 해결 후 재개 가능 여부를 확인합니다. |
| FAILED / CANCELLED / RETRY_WAIT | 실패 / 취소 / 재시도 대기. 이벤트와 오류 코드를 확인합니다. |

전역 FIFO에서 한 번에 한 작업을 실행합니다. 개별 Item 실패는 보존된 실패 목록에서 확인합니다.

- **재시작 단계** 기본값 `FAILED_STAGE`는 실패 단계부터 재처리합니다. 필요할 때만 COLLECT/PROCESS/EMBED/INDEX를 선택합니다.
- **Item 재처리**는 재시도 가능한 개별 실패에 사용합니다.
- **실패 Item 전체 재처리**는 선택한 작업의 실패 항목에 대한 일괄 요청입니다. 실패 목록 표시는 100개씩 페이지로 나뉩니다.
- **작업 재개**는 PAUSED/BLOCKED 상태이고 관리 권한이 있을 때 사용합니다. 인증·무결성 등 중단 원인을 먼저 해결합니다.
- **Job 이벤트**, **오류 · 진단 로그**를 펼쳐 결과를 확인합니다. 요청 후 다시 새로 고침합니다.

실패 목록 조회에는 `project_read`, 재처리·재개에는 `project_manage`가 필요합니다. 원본 Codebeamer/Polarion 내용을 수정하는 기능은 아닙니다.

## 9. 백업 · 패키지

### 프로젝트 Export/Import

1. **패키지 프로젝트**를 선택합니다.
2. **프로젝트 Export**로 작업을 생성하고, 작업 목록에서 완료를 확인합니다.
3. **패키지 목록 조회**를 누르고 준비된 Artifact의 **다운로드**를 선택합니다. 참조·크기·SHA256을 확인합니다.
4. Import할 때는 일치하는 대상 프로젝트를 선택하고 **ZIP 패키지 파일**을 지정합니다.
5. **패키지 업로드 · 검증**으로 검증된 Artifact 참조와 SHA256을 받습니다. 임의 서버 경로나 URL을 넣는 기능은 아닙니다.
6. 자동 입력된 **검증된 Artifact 참조**, **예상 SHA256**을 확인하고 **병합 Import 작업 생성**을 누릅니다.

Import는 `MERGE_ONLY`입니다. 누락 Item을 삭제하지 않고, 중복은 변경 없이 처리하며 같은 revision의 상충 내용은 격리합니다. 원본 프로젝트·서버 식별이 맞아야 합니다. 가져온 자료는 즉시 검색 활성 상태가 되지 않으므로 PROCESS/EMBED/INDEX 준비와 실행이 필요합니다. ZIP에는 실제 원본과 첨부가 포함될 수 있으므로 Git·Notion에 올리지 않습니다.

### 로컬 백업·격리 복구

관리자 세션으로 **수동 백업 생성 → 백업 목록 조회**를 사용합니다. 복구하려면 백업을 선택하고 **복구 사전 검증 → 격리 복구 자료 생성** 순서로 진행합니다. 사전 검증 결과는 만료되는 일회성 확인 값이므로 백업을 바꾸거나 사용한 뒤에는 다시 검증합니다.

결과의 `RAW_ONLY_REBUILD_REQUIRED`는 원본 중심 자료이며 재처리·임베딩·인덱스 재구축이 필요하다는 뜻입니다. `REREGISTRATION_REQUIRED`는 인증을 다시 등록해야 한다는 뜻입니다. **현재 운영 DB를 덮어쓰거나 복구 환경으로 자동 전환하는 기능이 아닙니다.**

**자동 백업 · 보관 정책**에서는 주기(초, 최소 60)와 보관 개수(최소 1)를 지정하고 **백업 정책 저장**을 누릅니다. 자동 실행에는 유지보수를 수행하는 Worker가 필요합니다.

## 10. 검색 평가: 무결성과 골든셋

### 무결성 검사

1. **품질 검사 프로젝트**를 선택합니다.
2. **무결성 검사**를 누릅니다. **보고서 작업 ID**에 생성된 작업 ID가 표시됩니다.
3. **작업 · 실패 목록**에서 완료를 확인합니다.
4. 검색 평가 화면으로 돌아오면 입력 상태가 초기화될 수 있으므로 작업 ID를 따로 기억해 **보고서 작업 ID**에 넣습니다.
5. **보고서 조회**를 누릅니다. 완료 전에는 현재 상태에서 실행할 수 없다는 안내가 나올 수 있습니다.

| 보고서 상태 | 의미 |
|---|---|
| PASS | 해당 검사 범위에서 실제 확인한 조건 충족 |
| FAIL | 원본·정규화·Chunk·인덱스 등의 불일치 확인. 이슈와 복구 권고 확인 |
| NOT VERIFIED | 기능·환경·버전 등의 조건으로 검증하지 못함. PASS로 해석하지 않음 |

검사는 읽기 전용이며 손상 자료를 자동 수정하지 않습니다. 실제 ALM에 다시 접속해 원본 완전성을 보증하는 검사도 아닙니다. 전체 상태뿐 아니라 개별 검사 결과와 영향 Item/revision·권고 조치를 함께 확인합니다.

데모에서는 합성 프로젝트의 **무결성 검사 → 보고서 조회**를 체험할 수 있습니다. 벡터·실제 ALM 등 미검증 항목이 표시될 수 있으며, 이를 데모 실행 오류와 혼동하지 않습니다.

### 세 검색 방식 평가

1. 준비된 인덱스·모델이 있는 프로젝트를 선택합니다.
2. **평가 검색어**를 입력합니다.
3. **정답 Item UID (한 줄에 하나)**에 정답 Item의 내부 UID를 중복 없이 입력합니다. Codebeamer 원본 Item ID와 다릅니다. Explorer의 `item_uid`로 확인합니다.
4. **평가 K**를 1~100 사이로 지정합니다.
5. **골든셋 저장**을 누른 뒤 **세 검색 방식 평가**로 Dense/Keyword/Hybrid 비교 작업을 생성합니다.
6. 완료 후 작업 ID로 **보고서 조회**를 누릅니다.

현재 UI는 한 검색어와 그 정답 목록을 하나의 골든셋으로 저장합니다. 여러 검색어 일괄 골든셋은 REST/CLI를 사용하며 [M6 Runbook](milestones/M6/RUNBOOK.md)을 참고합니다. 검색어·프로젝트·정답을 수정하면 이전 골든셋/작업 선택이 초기화되므로 다시 저장합니다.

Precision@K는 상위 K에서 정답 비율(K가 분모), Recall@K는 정답 집합 중 검색한 비율, MRR은 첫 정답 순위의 역수입니다. Item 단위로 중복을 제거합니다. 실행 PASS가 실제 모델 의미 검색 품질의 합격을 뜻하지는 않습니다.

## 11. 감사 로그와 문제 해결

**감사 로그 → 로그 새로 고침**으로 관리자 감사 기록을 조회합니다. 현재 UI에는 원격 Notion 전송을 설정·실행하는 메뉴가 없습니다.

| 증상 | 확인할 내용 |
|---|---|
| 브라우저가 열리지 않음 | 서버 터미널 오류, HTTPS 주소, SSH 터널을 브라우저 PC에서 실행했는지 확인 |
| 화면은 열리지만 Available이 아님 | 같은 Origin의 `/api/v1/healthz`와 API 프록시 확인 |
| 인증이 만료되었습니다 | ALM RAG 계정/키로 다시 연결. ALM 서버 비밀번호와 구분 |
| 이 작업을 실행할 권한이 없습니다 | 관리자 세션 여부, API 키의 프로젝트 범위와 권한 확인 |
| 항목을 찾을 수 없거나 접근할 수 없습니다 | UID·프로젝트·접근 범위 확인. 권한 오류를 우회하지 않음 |
| 입력값과 설정을 확인해 주세요 | 필수 필드·자격증명 참조 형식·ID·Top K 범위 확인 |
| 현재 상태에서 실행할 수 없습니다 | 사전 검증, 작업 상태, 보고서 완료 여부, 설정 변경 여부 확인 |
| 실제 서버 연결이 안 됨 | 데모 실행 여부, 비밀번호 참조, API·Worker의 live/allowlist 설정, 인증서·네트워크 확인 |
| 작업이 계속 QUEUED | 같은 DB를 사용하는 Worker 실행 여부와 선행 FIFO 작업 확인 |
| 검색 결과 없음 | 프로젝트 선택·필터·INDEX 완료·활성 generation·모델/벡터 준비 상태 확인 |

UI 오류는 의도적으로 원문 서버 응답을 그대로 표시하지 않습니다. 문제 보고에는 실행 방식, 화면 이름, 오류 문구와 비밀 값을 제거한 작업 ID·오류 코드를 사용합니다. 실제 비밀번호·토큰·고객 원문·첨부·DB·화면 캡처를 공개 저장소에 올리지 않습니다.

## 12. 이 설명서의 범위

이 문서는 현재 UI·서버 구현을 대조한 사용 절차입니다. 문서 작성 자체가 실제 Codebeamer/Polarion·모델 연결 검증을 뜻하지 않습니다. 기존 합성 테스트 및 Linux CI 증거는 [원격 CI 보고서](milestones/M6/REMOTE_CI_REPORT.md)에, 남은 실제 환경 검증은 [Open Issues](review/OPEN_ISSUES.md)에 구분되어 있습니다.
